# Argus

Argus は、登録した Web ページの更新有無を手動で確認するための Windows デスクトップアプリです。

小説サイト、ブログ、お知らせページ、更新履歴ページなどを毎回ブラウザで開いて確認する手間を減らすことを目的としています。

アプリ名は、ギリシャ神話に登場する百眼の巨人「アルゴス」に由来します。  
複数のページを見張り、前回確認時との差分を見つけるアプリとして、この名前を採用しています。

---

## 目的

Argus は、以下のような用途を想定しています。

- 小説サイトの作品ページが更新されたか確認する
- ブログやお知らせページの新着を確認する
- 配布ページや更新履歴ページの変更を確認する
- 毎回複数サイトを手動で開いて確認する手間を減らす

自動監視や通知ではなく、ユーザーがアプリを起動して「チェック」ボタンを押したタイミングで更新確認を行う、シンプルな手動チェック型アプリを目指します。

---

## 初期方針

まずは Windows 専用の WinForms アプリとして実装します。

初期 MVP 完了後は、既存 WinForms 版を残したまま Avalonia UI 版を試験追加し、Core を再利用できるか評価します。Avalonia への正式移行や WinForms 版の廃止は PoC の結果を確認してから別途判断します。Wails、Tauri などによる再構築は引き続き将来候補とします。

ただし、初期実装ではクロスプラットフォーム対応よりも、以下を優先します。

- 小さく作る
- 実際に使える形にする
- 誤検知をできるだけ抑える
- UI とチェックロジックを分離する
- 後から作り直しやすい構成にする

---

## 開発手法

Argus は、仕様駆動開発（SDD）とテスト駆動開発（TDD）を組み合わせて開発します。

SDD では、実装前に要件、設計、タスクを次の文書へ記載し、仕様と実装の対応関係を明確にします。

- 要件: `Design/requirement.md`
- 設計: `Design/design.md`
- タスク: `Design/tasks.md`

TDD では、設計とタスクに基づき、テスト可能な振る舞いを小さな単位で次の順に実装します。

1. Red: 期待する振る舞いを表す失敗するテストを書く
2. Green: テストを通すための最小限の実装を行う
3. Refactor: テストを維持したまま設計とコードを改善する

要件変更時は、実装やテストより先に仕様文書を更新します。Core のロジックは UI から分離し、実際の Web サイトへ依存しない自動テストで検証します。

## 開発環境での起動

.NET 8 SDKをインストールしたWindows上で、リポジトリのルートから次を実行します。

```powershell
dotnet restore
dotnet build Argus.sln
dotnet run --project Argus.WinForms
```

Windowsでの通常開発とAvalonia PoCの主要確認には Visual Studio Community 2022 を使用します。Avaloniaプロジェクト追加後は、同じ `Argus.sln` からWinForms版とAvalonia版をそれぞれスタートアッププロジェクトに設定し、F5起動、Debug / Releaseビルド、Test Explorerでの全テストを確認します。Avalonia用IDE拡張はXAML編集やプレビューの支援に限定し、ビルドの必須条件にはしません。

Avalonia PoCのWindows配布確認では、Visual Studio 2022の `Windows-x64-SingleFile` 発行プロファイルを使用し、.NETランタイムを同梱した `Argus.Avalonia.exe` 1ファイルを `artifacts/Argus-Avalonia-win-x64-single/` へ生成します。

macOSではVS Codeでリポジトリを開き、.NET 8 CLIによる復元、ビルド、`dotnet run`での起動を軽く確認します。macOSでの全機能網羅、UI詳細、配布パッケージ検証は行いません。

初回起動時は空の一覧が表示され、保存ファイルが存在しない場合は空のスキーマv1文書を作成します。「追加」から名前とHTTP/HTTPS URLを入力すると、最初の監視対象を登録できます。

主な操作:

- 「全件チェック」: 有効な監視対象をすべて手動で確認する
- 「選択をチェック」: 一覧で選択した有効な対象だけを確認する
- 「ブラウザで開く」: 選択した1件をWindowsの既定ブラウザで開く
- 「追加」「編集」「削除」: 監視対象を管理する
- Ctrlキーを押しながら行を選択: 複数の監視対象を選択する

チェックはボタン操作時だけ実行されます。自動監視や常駐処理は行いません。

## 主な機能

### 監視対象の管理

登録したい Web ページを監視対象として管理します。

登録項目の例:

- 名前
- URL
- 監視モード
- 有効 / 無効
- メモ

選択できる監視モードは「HTMLテキスト比較」「HTML全体比較」「CSSセレクタ比較」です。

---

### 手動チェック

ユーザーが「チェック」ボタンを押したタイミングで、登録済みの監視対象を確認します。

初期版では、自動チェック、常駐監視、スケジュール実行は行いません。

---

### 更新状態の表示

チェック結果は一覧画面に表示します。

想定する状態:

- 未確認
- 初回取得
- 更新なし
- 更新あり
- エラー

初回チェック時は比較対象が存在しないため、「更新あり」ではなく「初回取得」として扱います。

---

### ブラウザで開く

更新があったページや登録済みページを、Windows の既定ブラウザで開けるようにします。

小説サイト向けの最新話チェックに対応した場合は、作品ページだけでなく最新話 URL を直接開けるようにする予定です。

---

## 監視モード

Argus では、検知したい範囲に応じて複数の監視モードを選択できます。

### HTML テキスト比較

HTML を取得し、script / style などを除去したうえでテキスト化し、前回の内容と比較します。

初期実装の標準モードとして想定しています。

---

### HTML 全体比較

ページ全体の HTML を比較します。

汎用性は高い一方で、広告、アクセス解析タグ、日時、ランキング、ランダム ID などによる誤検知が起きやすいため、必要に応じて使用します。

---

### CSS セレクタ比較

指定した CSS セレクタに一致する部分だけを抽出して比較します。

お知らせ一覧、本文、目次、更新履歴など、必要な範囲だけを対象にできるため、誤検知を抑える上で重要なモードです。

---

### 最新エピソード比較

小説サイト向けの監視モードです。

作品ページから最新話情報を抽出し、前回確認時の最新話 URL やタイトルと比較します。

想定対象:

- カクヨム
- 小説家になろう
- ハーメルン
- ノベルアップ+
- その他の小説サイト

初期実装では汎用モードを優先し、その後にカクヨムなどのサイト別対応を追加する予定です。

---

## 誤検知対策

単純な HTML 全体比較だけでは、ユーザーにとって意味のない変化も更新として検知してしまう可能性があります。

そのため、以下の方針で誤検知を抑えます。

- script タグを除去する
- style タグを除去する
- HTML コメントを除去する
- 空白や改行を正規化する
- 必要に応じて本文テキストだけを比較する
- CSS セレクタで比較対象範囲を絞る
- 小説サイトではページ全体ではなく最新話情報を比較する
- エラー時は前回データを上書きしない

## データ保存

監視対象と前回チェック結果は JSON ファイルに保存します。

保存先:

```text
%APPDATA%\Argus\targets.json
```

JSONは `schemaVersion: 1`、UTF-8（BOMなし）、camelCase、文字列の列挙値、UTC日時で保存します。保存時は一時ファイルを経由し、保存に失敗した場合は既存のJSONと画面上の変更前データを維持します。

ファイルが空、不正、または未対応のスキーマである場合は、既存ファイルを上書きせず、主要操作を無効化してエラーを表示します。初期版では外部DBを使用しません。

## プロジェクト構成

```text
Argus/
  Argus.WinForms/
    Program.cs
    Forms/
      MainForm.cs
      TargetEditForm.cs
    Presentation/
    Services/

  Argus.Core/
    Models/
    Persistence/
    Services/

  Argus.Core.Tests/
    Models/
    Persistence/
    Services/

  Argus.WinForms.Tests/
    Forms/
    Presentation/

  Argus.Avalonia/          # PoCの代替フロントエンド
    Views/
    ViewModels/
    Services/

  Argus.Avalonia.Tests/    # PoCのViewModelテスト
    ViewModels/

  UI/
    index.html
    styles.css
    app.js
```

WinForms側には画面表示とイベント接続だけを置き、更新チェック、HTML解析、状態判定、保存はCore側に分離しています。Avalonia PoCでも同じCoreを参照し、MVVMで画面とUI状態を構成します。`UI/` のHTMLモックは承認済みの設計資料であり、WinFormsまたはAvaloniaの実行時には読み込みません。

## 初期 MVP

最初の実装では、以下を目標にします。

- WinForms アプリを起動できる
- JSON から監視対象を読み込める
- 監視対象を一覧表示できる
- 監視対象を画面から追加 / 編集 / 削除できる
- 「夏」をテーマにした明るく爽やかな配色で表示できる
- 画面上でコピーライト、アプリのバージョン、デバッグビルドかどうかを確認できる
- HTMLテキスト、HTML全体、CSSセレクタ比較で更新確認できる
- 手動チェックできる
- 結果を一覧に反映できる
- 成功時のみ前回データを更新できる
- JSON に保存できる
- 選択した URL をブラウザで開ける

## Avalonia UI PoC

Avalonia UI PoCでは、現行WinForms版を削除または置換せず、同じ `Argus.Core` とschema v1 JSONを利用する代替フロントエンドを追加します。

PoCの対象:

- 監視対象の一覧、追加、編集、削除
- 全件チェック、選択項目チェック、結果表示
- HTMLテキスト、HTML全体、CSSセレクタ比較
- OSの既定ブラウザで開く操作
- コピーライト、バージョン、Debugビルド表示
- Avalonia標準Fluent ThemeとOSのライト／ダーク設定への追従

評価方針:

- Core再利用性は「高」、Avalonia導入難易度は「中」と見込む
- WindowsをPoCの合否を判断する主環境とし、Visual Studio 2022で全機能と回帰を確認する
- macOSはVS Codeと.NET CLIで起動、JSON読み込み、一覧表示、1件の手動チェック、既定ブラウザ起動を軽く確認する
- WinForms版とAvalonia版はWindows上で同じJSONを使用するが、同時起動はしない
- Linux対応、UI自動テスト、正式移行、WinForms版廃止、プロセス間ファイル排他はPoC対象外とする

成功時も自動的に全面移行せず、Core変更の有無、WinForms版への影響、WindowsとmacOSの検証結果、全面移行時の課題、推奨度をまとめて判断材料とします。

## 初期版で対応しないこと

初期版では以下は対象外とします。

- 自動チェック
- 常駐監視
- LINE 通知
- Slack 通知
- メール通知
- ログイン必須サイトの監視
- CAPTCHA が必要なサイトの監視
- JavaScript 実行後の SPA 解析
- Playwright 等によるブラウザレンダリング
- 外部 DB 連携

---

## 開発メモ

まずは「自分が実際に使える最小機能」を優先します。

高度な監視ツールを目指すのではなく、PC を起動して Argus を開き、チェックボタンを押すだけで「今日は更新されているか」が分かる状態を目標にします。
