- 情報源: `Design/project-overview.md`
- 作成日: 2026-07-15

## 2. 背景

ユーザーは、小説サイト、ブログ、お知らせページ、配布ページ、更新履歴ページなど、複数の Web ページをブラウザで個別に開き、更新の有無を確認しています。

この確認作業には手間がかかるため、登録済みの複数ページを一括で確認し、前回確認時からの更新有無を把握できるデスクトップアプリを提供します。

---

## 3. 目的

Argus の目的は、ユーザーが任意のタイミングで更新チェックを実行し、登録した Web ページが前回確認時から変化したかを一覧で確認できるようにすることです。

初期 MVP では、高度な自動監視ツールではなく、次の利用体験を実現することを目標とします。

1. ユーザーが PC 上で Argus を起動する
2. 登録済みの監視対象を一覧で確認する
3. ユーザーがチェック操作を実行する
4. 各ページの更新状態を一覧で確認する
5. 必要なページを既定のブラウザで開く

---

## 4. 用語

| 用語 | 定義 |
| --- | --- |
| 監視対象 | 更新確認の対象として Argus に登録された Web ページ |
| チェック | ユーザー操作により Web ページを取得し、前回データと比較する処理 |
| 前回データ | 直前に正常終了したチェックで保存された比較用データ |
| 初回取得 | 比較可能な前回データが存在せず、今回の取得内容を基準として保存した状態 |
| 更新なし | 今回取得した比較対象の内容が前回データと同一である状態 |
| 更新あり | 今回取得した比較対象の内容が前回データと異なる状態 |
| エラー | Web ページの取得またはチェック処理を正常に完了できなかった状態 |
| HTML テキスト比較 | HTML から比較に不要な要素を除去してテキスト化し、正規化した内容を比較する方式 |
| HTML 全体比較 | 取得した HTML 文字列全体を比較する方式 |
| CSS セレクタ比較 | CSS セレクタに一致する要素だけを抽出して比較する方式 |

---

## 5. 対象範囲

### 5.1 初期 MVP の対象

- Windows デスクトップアプリとして起動する
- JSON ファイルから監視対象と前回データを読み込む
- 登録済みの監視対象を一覧表示する
- 監視対象を画面から追加、編集、削除する
- ユーザー操作によって手動チェックを開始する
- HTML テキスト比較によって更新有無を判定する
- HTML 全体比較または CSS セレクタ比較を監視対象ごとに選択できる
- チェック結果を一覧へ反映する
- 更新ありと判定した監視対象について、前回の比較対象と今回の比較対象の差分内容を表示する
- 正常終了したチェック結果を JSON ファイルへ保存する
- 選択した監視対象の URL を OS の既定ブラウザで開く

### 5.2 初期 MVP の対象外

- 自動チェック
- 常駐監視
- スケジュール実行
- LINE 通知
- Slack 通知
- メール通知
- ログイン必須サイトの監視
- CAPTCHA が必要なサイトの監視
- JavaScript 実行後の SPA 解析
- Playwright などを利用したブラウザレンダリング
- 外部データベースとの連携
- 小説サイト向け最新エピソード比較
- チェック履歴の表示
- 設定のインポート、エクスポート
- 最新話 URL を直接開く機能
- Wails、Tauri など、Avalonia 以外の UI 技術への移行

### 5.3 Avalonia 正式版の対象

- `Argus` を `.NET 10` と Avalonia で実装する唯一の正式 UI とする
- Windows 10 / Windows 11 x64 と macOS 14 以降 Apple Silicon を正式サポートする
- `Argus.Core` のモデル、永続化、取得、比較、チェック調停処理を再利用する
- 現行の schema v1 JSON と Windows の既存保存データを維持する
- Windows は自己完結型 single-file executable、macOS は自己完結型 `Argus.app` を配布する
- WinForms 版とそのテストは正式採用時に廃止する

Linux、Intel Mac、Apple Developer 署名・公証、インストーラー、自動更新は v0.2.0 の対象外とします。

### 5.4 MVP 後の対象

- 監視対象の設定を専用のポータブル JSON ファイルへエクスポートする
- ポータブル JSON ファイルから監視対象の設定をインポートする
- 設定の移行では前回の比較用データやチェック状態を引き継がず、インポートした対象を初回取得として扱う
- 有効な監視対象を設定した間隔で自動チェックする
- 自動チェックで更新ありを検出したとき、Windows または macOS の OS 標準ローカル通知を表示する
- 未確認の更新あり対象数を Windows のタスクバーアイコンまたは macOS の Dock アイコンへバッジ表示する
- LINE、Slack、メールなど外部サービスへの通知は、別途要件を追加するまで対象外とする

---

## 6. 利用者

利用者は、Windows 10 / Windows 11 x64 または macOS 14 以降 Apple Silicon を使用し、複数の公開 Web ページの更新有無を任意のタイミングで確認したい個人ユーザーとします。

初期 MVP では複数ユーザー、アカウント、権限管理を扱いません。

---

## 7. 機能要件

### FR-001 アプリケーションの起動

Argus は、Windows デスクトップアプリとして起動できなければなりません。

受け入れ条件:

- Windows 10 または Windows 11 上でアプリを起動できる
- 起動後に監視対象の一覧画面が表示される

### FR-002 監視対象データの読み込み

Argus は、起動時に所定の JSON ファイルから監視対象と前回チェック結果を読み込まなければなりません。

想定保存先:

```text
%APPDATA%\Argus\targets.json
```

監視対象が保持する項目:

- ID
- 名前
- URL
- 監視モード
- 有効 / 無効
- メモ
- 前回の比較用データ

受け入れ条件:

- 正常な JSON ファイルから監視対象を復元できる
- 復元した監視対象が一覧へ表示される
- JSONが空、不正、または未対応の形式の場合はエラーを表示する
- JSONを正常に読み込めない場合は、チェック、監視対象管理、ブラウザ起動などの主要操作を無効化する
- JSONを正常に読み込めない場合は、既存ファイルを上書きしない

具体的な必須項目、初期値、JSONスキーマ、ファイル状態ごとの動作は `Design/design.md` で定義します。

### FR-003 監視対象の一覧表示

Argus は、読み込んだ監視対象を一覧表示しなければなりません。

一覧では、少なくとも各監視対象を識別でき、チェック結果を確認できなければなりません。

受け入れ条件:

- 複数の監視対象を一覧表示できる
- 各監視対象の名前または URL を確認できる
- 各監視対象の現在のチェック状態を確認できる

一覧へ表示する列、並び順、無効な監視対象の表示方法は `Design/design.md` で定義します。初期 MVP では絞り込み機能を設けません。

### FR-004 手動チェックの開始

Argus は、ユーザーが画面上のチェック操作を行ったときに、登録済みの監視対象に対する更新チェックを開始しなければなりません。

チェック操作は、次の二つに分けます。

- 全件チェック: 有効な監視対象をすべてチェックする
- 選択項目チェック: 一覧で選択した有効な監視対象だけをチェックする

チェック処理の実行中も、ユーザーによる新たなチェック操作を許可します。同じ監視対象がチェック中の場合も、再度チェックを開始できるものとします。

受け入れ条件:

- ユーザー操作がない状態で自動的にチェックを開始しない
- 全件チェックによって、有効な監視対象を一度の操作ですべて確認できる
- 選択項目チェックによって、一覧で選択した有効な監視対象だけを確認できる
- チェック処理の実行中でも、全件チェックまたは選択項目チェックを新たに開始できる
- 同じ監視対象のチェック処理が実行中でも、その監視対象を再度チェックできる

備考:

- 同じ監視対象のチェックが重複した場合、画面には時系列で最後に完了したチェックの結果を表示します。
- 最後に完了したチェックが正常終了した場合は、その結果を前回データとして保存します。
- 最後に完了したチェックがエラーの場合は、画面にエラーを表示しますが、前回の正常なデータは上書きしません。

### FR-005 Web ページの取得

Argus は、チェック対象の URL から HTML を取得しなければなりません。

受け入れ条件:

- 公開されている HTTP または HTTPS の Web ページを取得できる
- HTTPヘッダー、BOM、HTML内の `meta charset` を用いて文字コードを判定できる
- 取得に失敗した場合は、その監視対象をエラーとして扱う
- 一つの監視対象でエラーが発生しても、他の監視対象の結果を失わない

備考:

- タイムアウト、リダイレクト、User-Agent、同時取得数は `Design/design.md` で定義します。
- 文字コード判定の優先順位は `Design/design.md` で定義します。

### FR-006 HTML テキストの正規化

Argus は、取得した HTML をテキスト比較に適した形式へ正規化しなければなりません。

初期 MVP の正規化では、少なくとも次を行います。

- `script` 要素の内容を比較対象から除外する
- `style` 要素の内容を比較対象から除外する
- HTML コメントを比較対象から除外する
- 空白と改行の差異を正規化する
- HTML をテキスト化する

受け入れ条件:

- `script`、`style`、HTML コメントだけの変化を更新として検知しない
- 正規化によって同一とみなせる空白または改行だけの変化を更新として検知しない
- ユーザーが閲覧する本文テキストが変化した場合は、比較結果へ反映される

備考:

- HTML の不正な構造、エンティティ、改行および連続空白の具体的な正規化規則は設計で定義します。

### FR-014 HTML 全体比較

Argus は、監視対象ごとに取得した HTML 文字列全体を比較対象として選択できなければなりません。

受け入れ条件:

- HTML 全体比較では、取得した HTML 文字列を加工せず比較用ハッシュへ変換する
- 要素、属性、コメント、空白のいずれかが変化した場合は比較結果へ反映される
- 従来の HTML テキスト比較を選択した対象の動作は変わらない

### FR-015 CSS セレクタ比較

Argus は、監視対象ごとに CSS セレクタを指定し、一致する要素だけを比較対象として選択できなければなりません。

受け入れ条件:

- CSS セレクタ比較を選択した場合は、CSS セレクタを必須とする
- 一致する全要素の外側 HTML を文書順に連結して比較する
- 一致要素内の要素、属性、テキストの変化が比較結果へ反映される
- 一致要素の外側だけの変化は比較結果へ反映されない
- CSS セレクタが不正、または一致する要素がない場合はエラーとして扱う
- CSS セレクタ比較のエラー時は前回の正常な比較用データを上書きしない

### FR-007 更新状態の判定

Argus は、今回取得して正規化した内容と前回データを比較し、監視対象ごとの状態を判定しなければなりません。

状態は次のいずれかとします。

| 状態 | 条件 |
| --- | --- |
| 未確認 | 現在の起動中にまだチェックしていない |
| 初回取得 | 前回データが存在せず、今回の取得に成功した |
| 更新なし | 今回の内容と前回データが同一だった |
| 更新あり | 今回の内容と前回データが異なった |
| エラー | 取得または比較処理に失敗した |

受け入れ条件:

- 前回データがない正常取得を「更新あり」ではなく「初回取得」と判定する
- 正規化後の内容が同一の場合は「更新なし」と判定する
- 正規化後の内容が異なる場合は「更新あり」と判定する
- 処理に失敗した場合は「エラー」と判定する

### FR-008 チェック結果の表示

Argus は、チェック結果を監視対象の一覧へ反映しなければなりません。

受け入れ条件:

- 監視対象ごとに「未確認」「初回取得」「更新なし」「更新あり」「エラー」のいずれかを確認できる
- 複数の監視対象について、それぞれの結果を区別できる

チェック日時とエラー概要の表示方法は `Design/design.md` で定義します。色やアイコンによる追加表現は初期 MVP の必須要件としません。

### FR-009 正常結果の保存

Argus は、正常にチェックできた監視対象について、次回比較に必要なデータを JSON ファイルへ保存しなければなりません。

受け入れ条件:

- 初回取得、更新なし、更新ありのチェック完了後に、次回比較に必要なデータを保存できる
- アプリを終了して再起動した後も、保存済みデータを前回データとして利用できる
- 保存先は `%APPDATA%\Argus\targets.json` を基本とする

### FR-010 エラー時の前回データ保護

Argus は、チェックに失敗した監視対象の前回データを上書きしてはなりません。

受け入れ条件:

- 通信エラーが発生しても、その監視対象の前回の正常な比較用データが保持される
- 比較処理でエラーが発生しても、その監視対象の前回の正常な比較用データが保持される
- 次回の正常なチェックで、保持された前回データと比較できる

### FR-011 既定ブラウザで開く

Argus は、ユーザーが選択した監視対象の URL を OS の既定ブラウザで開けなければなりません。

受け入れ条件:

- 一覧から監視対象を選択して、その URL を開く操作を実行できる
- URL が OS の既定ブラウザで開かれる
- URL を開けない場合にアプリが異常終了しない

### FR-012 監視対象の追加・編集・削除

Argus は、監視対象を画面から追加、編集、削除できなければなりません。

追加または編集できる項目は次のとおりです。

- 名前
- URL
- 監視モード
- 有効 / 無効
- メモ

選択できる監視モードは HTML テキスト比較、HTML 全体比較、CSS セレクタ比較とします。CSS セレクタ比較では CSS セレクタも入力します。

受け入れ条件:

- 新しい監視対象を追加し、一覧へ反映できる
- 既存の監視対象を選択し、その内容を編集できる
- 既存の監視対象を確認操作後に削除できる
- 名前が空または空白だけの場合は保存できない
- URLが絶対HTTP/HTTPS URLでない場合は保存できない
- 追加、編集、削除の結果がJSONへ保存される
- アプリを再起動しても追加または編集した内容が復元され、削除した対象が復元されない
- 保存に失敗した場合は、画面上および保存済みの変更前データを維持する
- URLを変更した場合は前回の比較データを破棄し、次回の正常チェックを「初回取得」として扱う
- 監視モードまたは CSS セレクタを変更した場合は前回の比較データを破棄し、次回の正常チェックを「初回取得」として扱う
- チェック実行中の監視対象は編集または削除できない

### FR-013 コピーライト、バージョン、ビルド種別の表示

Argus は、メイン画面にコピーライト表記とアプリケーションのバージョン番号を表示しなければなりません。

コピーライトは次の表記とします。

```text
Copyright © 2026 SIA-ACT
```

デバッグビルドでは、開発用ビルドであることをユーザーが識別できる表示を追加しなければなりません。Releaseビルドではデバッグ表示を行いません。

受け入れ条件:

- メイン画面上で `Copyright © 2026 SIA-ACT` を確認できる
- メイン画面上でバージョン番号を確認できる
- コピーライト表記はビルド時のアセンブリ情報から取得する
- 表示するバージョン番号はビルド時のアセンブリ情報から取得する
- コピーライトとバージョン番号を画面コードへ直接記述しない
- Debug構成でビルドしたアプリには `DEBUG` と表示される
- Release構成でビルドしたアプリには `DEBUG` が表示されない
- バージョン番号とデバッグ表示が、通常の操作やメッセージ表示を妨げない

### FR-016 Avalonia クロスプラットフォーム UI

Argus は、同じ Core ロジックを利用する Avalonia UI として正式に動作しなければなりません。

受け入れ条件:

- `Argus` から `Argus.Core` を参照し、Core から Avalonia を参照しない
- Windows 10 / Windows 11 x64 と macOS 14 以降 Apple Silicon で起動できる
- JSON 読み込みエラー時の操作制限を含め、監視対象一覧を表示できる
- 監視対象を追加、編集、削除できる
- 全件チェックと選択項目チェックを実行し、結果を一覧へ反映できる
- HTML テキスト、HTML 全体、CSS セレクタの各比較方式を利用できる
- 選択した監視対象を OS の既定ブラウザで開ける
- コピーライト、バージョン、Debug ビルドの識別情報を確認できる
- 一覧の監視サイト情報が常に判読でき、列境界のドラッグで列幅を変更できる
- 一覧の列境界をダブルクリックすると、その列の内容に合わせて列幅を自動調整できる
- 一覧の各列は内容を判読できる最小幅を維持し、一つの列を広げても他の列を最小幅未満へ縮めない
- 一覧には横方向と縦方向のスクロールバーを表示し、画面内へ収まらない列と行へ移動できる
- 正常結果だけを現行 schema v1 JSON へ保存し、エラー時は前回の正常データを上書きしない
- アプリ名、成果物名、画面上の製品名を `Argus` に統一する
- Windows と macOS の双方で JSON 読み込み、一覧表示、手動チェック、既定ブラウザ起動を確認できる

### FR-017 正式ユーザーマニュアルの表示

Argus は、Avalonia 正式版の操作方法を説明するオフラインユーザーマニュアルをアプリから表示できなければなりません。

受け入れ条件:

- メイン画面にアイコンと文字ラベルを持つ「マニュアル」ボタンを常時表示する
- 一覧の選択状態や起動データの読み込み結果にかかわらずボタンを利用できる
- ボタンを実行すると、埋め込み済みの `Manual/index.html` と画像をOSの一時領域へ展開する
- 展開したマニュアルをOSの既定ブラウザで開く
- マニュアルはインターネット接続なしで本文と画像を閲覧できる
- 展開またはブラウザ起動に失敗した場合は、アプリを終了せず利用者向けエラーを表示する
- Windowsのsingle-file `Argus.exe` とmacOSの `Argus.app` の双方にマニュアルを内包する
- マニュアルの説明、画面画像、バージョンがAvalonia正式版の実装と一致する

### FR-018 差分内容の表示

Argus は、更新ありと判定した監視対象について、前回の比較対象と今回の比較対象の差分内容を表示できなければなりません。

受け入れ条件:

- 更新ありの結果を持つ監視対象を選択し、差分表示操作を実行できる
- 差分表示では、比較方式に応じた比較対象の追加、削除、変更を利用者が識別できる
- HTMLテキスト比較では、script、style、HTMLコメントを除外し、空白と改行を正規化した比較対象同士の差分を表示する
- HTML全体比較では、取得したHTML文字列全体同士の差分を表示する
- CSSセレクタ比較では、一致要素の外側HTMLを文書順に連結した比較対象同士の差分を表示する
- 初回取得、更新なし、エラーの結果では、差分表示操作を実行できない、または差分がない理由を表示する
- 差分表示に使用する比較対象は、直近の正常チェック結果として保持し、チェック履歴は保存しない
- 既存のschema v1 JSONに比較対象の内容が保存されていない場合も、ハッシュによる更新判定を継続できる
- 既存のschema v1 JSONに比較対象の内容がない監視対象では、比較対象が保存されるまで差分を表示できないことを利用者へ明示する
- 差分生成または表示に失敗しても、前回の正常な比較用データを上書きしない

### FR-019 設定のインポート・エクスポート（MVP後）

Argus は、監視対象の設定をポータブルな JSON ファイルへエクスポートし、別の Argus 環境へインポートできなければなりません。

本機能における「設定」は、監視対象の名前、URL、監視モード、CSS セレクタ、有効 / 無効、メモを指します。前回の比較用データ、チェック状態、チェック日時は設定に含めません。

受け入れ条件:

- メイン画面から、登録済みの全監視対象の設定をユーザーが指定した JSON ファイルへエクスポートできる
- エクスポートした JSON は UTF-8、camelCase、専用の形式識別子とバージョンを持つ
- エクスポートした JSON に前回の比較用データ、チェック状態、チェック日時を含めない
- JSON ファイルを指定してインポートを開始でき、読み込み前に現在の設定が置き換わることを確認できる
- インポート前にファイル全体を検証し、名前、URL、監視モード、CSS セレクタの入力規則に違反する設定を反映しない
- 正常にインポートした監視対象は新しい識別子を持ち、前回データがない「初回取得」の状態になる
- JSON が空、不正、未対応の形式または未対応のバージョンの場合は、現在の設定を変更せずエラーを表示する
- インポートをキャンセルした場合、または保存に失敗した場合は、現在の設定と保存済み JSON を維持する
- インポートまたはエクスポートに失敗しても、アプリが異常終了しない

### FR-020 自動監視（MVP後）

Argus は、ユーザーが有効にした自動監視設定に従い、登録済みの有効な監視対象を設定した間隔で自動チェックできなければなりません。

受け入れ条件:

- 自動監視を有効または無効に切り替えられる
- 自動監視の実行間隔を設定できる
- アプリが起動していない時間帯にも監視するかを選択できる
- 自動チェックでは、有効な監視対象だけを対象とする
- 自動チェックは、手動チェックと同じ取得、比較、保存、エラー時のデータ保護処理を利用する
- 自動チェックの実行中に、同じ監視対象に対する別の自動チェックを重複開始しない
- 自動監視が有効な場合、アプリがバックグラウンドで動作している間も設定した間隔でチェックできる
- アプリが起動していない時間帯にも監視する設定を選択した場合は、対応する OS のログイン時起動またはスケジュール実行を利用できる
- 自動チェックを停止または無効化した場合、実行中の処理へキャンセルを通知し、新しい自動チェックを開始しない
- 自動チェックでエラーが発生しても、対象の前回の正常な比較用データを上書きしない

### FR-021 更新通知と未確認件数バッジ（MVP後）

Argus は、自動チェックで更新ありを検出した監視対象について、OS 標準のローカル通知とアプリケーションアイコンの未確認件数バッジを表示できなければなりません。

受け入れ条件:

- 通知はアプリ内のモーダルなメッセージボックスではなく、Windows または macOS の OS 標準通知として表示する
- 通知には更新を検出した監視対象の名前と、Argus で確認できることを表示する
- 同じ監視対象が更新なしのままの場合、同じ更新について通知を繰り返さない
- 更新を確認済みにした後に新たな更新を検出した場合は、再度通知する
- 未確認件数は、未確認の更新あり状態を持つ監視対象の件数とし、チェック実行回数や通知回数では数えない
- 未確認件数を Windows のタスクバーアイコンまたは macOS の Dock アイコンへ数値バッジとして表示できる
- 未確認件数が 0 件になった場合は、アイコンのバッジを消去する
- 通知を選択した場合は Argus を起動または前面表示し、該当する監視対象を選択できる
- ユーザーが通知または一覧上の確認操作を完了した監視対象を、確認済みとして扱える
- 未確認状態と通知設定はアプリ再起動後も必要な範囲で復元できる
- OS の通知権限が拒否された場合や通知表示に失敗した場合でも、チェック結果の表示と保存を失敗させない
- 通知を無効にしても、自動監視と更新結果の保存は継続する
- 通信エラーや比較エラーの通知、LINE、Slack、メールなど外部サービスへの通知は本要件に含めない

## 8. 非機能要件

### NFR-001 対応環境

- Windows 10 / Windows 11 x64 と macOS 14 以降 Apple Silicon を対象とする
- UI には Avalonia を使用する
- C# および .NET 10 以降を使用する

### NFR-002 配布

Windows版は.NETランタイムを同梱したself-contained single-file executable、macOS版は.NETランタイムを同梱したself-contained app bundleとします。

備考:

- Windows発行物は `Argus.exe` 1ファイルとする
- HTMLマニュアルと画像は実行ファイルへ埋め込み、Windows発行物へ外部ファイルを追加しない
- macOS発行物は `osx-arm64` の `Argus.app` とする
- 互換性を優先してトリミングとReadyToRunを使用しない
- Apple Developer署名と公証は後続タスクとする

### NFR-003 データ永続化

- 監視対象と前回チェック結果は JSON 形式でローカルへ保存する
- 差分表示に必要な比較対象の内容は、直近の正常チェック結果についてのみ保存する
- 比較対象の内容は外部サービスへ送信せず、チェック履歴として蓄積しない
- 初期 MVP では外部データベースを使用しない
- チェックエラーによって前回の正常データを失わない
- 運用中の `targets.json` と設定移行用のポータブル JSON は別形式として扱う
- 設定移行用の JSON は UTF-8、camelCase、明示的な形式識別子とバージョンを持つ
- 設定のインポートは全件検証後に原子的に反映し、検証または保存に失敗した場合は既存データを変更しない

### NFR-004 誤検知の抑制

- 初期 MVP の標準監視モードには HTML テキスト比較を使用する
- 比較前に `script`、`style`、HTML コメントを除外する
- 比較前に空白と改行を正規化する
- 誤検知を抑えるための追加方式は、初期 MVP の完了後に検討する

### NFR-005 保守性と移植性

- UI 処理と更新チェックロジックを分離する
- HTML 取得、正規化、比較、差分生成、保存の責務を分離する
- Avalonia を変更する場合にもチェックロジックを再利用できる構成とする

### NFR-006 操作方針

- 更新チェックはユーザーの明示的な操作によって開始する
- 初期 MVP ではバックグラウンドでの自動監視を行わない
- PC を起動し、Argus を開いてチェック操作を行うだけで更新有無を把握できることを目標とする
- アプリ終了時は実行中または待機中のチェックへ即時キャンセルを通知し、完了を待たずに終了する

### NFR-007 テスト可能性と品質保証

- UI と Core のロジックを分離し、Core の振る舞いを UI なしで自動テストできること
- HTML の正規化、比較、状態判定、データ保護の主要な振る舞いを自動テストで検証できること
- 初回取得、更新なし、更新あり、通信エラーを自動テストで検証すること
- エラー時に前回の正常データが保持されることを自動テストで検証すること
- 比較方式ごとの差分生成、差分表示対象外の状態、既存JSONとの後方互換性を自動テストで検証すること
- 自動テストは実際の Web サイトの状態に依存せず、繰り返し同じ結果を得られること
- テスト可能な機能は、原則として失敗するテスト、最小限の実装、リファクタリングの順で開発すること

### NFR-008 UIテーマと視認性

- Avalonia標準のFluent Themeを使用する
- ライトを既定とし、画面上でライト／ダークを切り替えられる
- 青系を基調に、背景、文字、ボタン、選択状態、無効状態、チェック結果を画面間で統一する
- 文字と背景のコントラストを確保し、長時間使用しても読みにくくならないこと
- 更新状態やエラー状態は色だけで表現せず、状態名の文字を必ず併記すること
- 操作可能、選択中、フォーカス中、無効の各状態を視覚的に区別できること

### NFR-009 Avalonia UI の構造とテーマ

- Avalonia 側は MVVM を基本とし、View に業務ロジックを置かない
- Core の公開 API とドメインモデルを再利用し、Avalonia 専用のドメインモデルを重複して作らない
- Avalonia 標準の Fluent Theme を使用し、外部 MVVM ライブラリや外部 UI テーマを追加しない
- ライトテーマを既定とし、画面上の切替操作でライト / ダークを選択できる
- 業務用プロダクトとして識別しやすい青系の配色を使用し、背景と文字のコントラストを確保する
- ボタンは背景色に対して十分なコントラストを持つ文字色を使用し、角丸を使用しない
- ヘッダー上の操作ボタンは通常、ホバー、押下、選択の全状態で文字とアイコンを判読できる配色とし、隣接する同種の操作は共通スタイルで統一する
- 主要な集計と操作には文字ラベルを残したまま補助アイコンを付け、アイコンだけに意味を依存させない
- Avalonia版は「目」とWebウィンドウを組み合わせた専用アプリアイコンを使用し、メイン画面、編集画面、メッセージ画面、Windowsのタスクバーと実行ファイルでArgusを識別できるようにする
- 既存の `assets/argus-banner.png` を監視対象一覧全体の薄い背景として活用し、通常行、選択行、列ヘッダー、スクロール操作の視認性を妨げない濃さで表示する
- 更新状態やエラー状態は色だけで表現せず、状態名の文字を併記する
- Core からのイベントを ViewModel へ反映する箇所以外では、UI Dispatcher への依存を増やさない

### NFR-010 クロスプラットフォーム検証環境

- Windows では Visual Studio 2026 を主要な開発・品質確認環境とする
- Windows ではソリューション読込、NuGet 復元、Debug / Release ビルド、F5 起動、全自動テスト、全機能の手動確認を行う
- macOS では VS Code と .NET 10 CLI を使用し、復元、ビルド、テスト、発行、起動と全受け入れ操作を確認する
- Avalonia 用 IDE 拡張機能は編集やプレビューの支援に限定し、ビルドの必須条件にしない
- Windows と macOS の双方の検証を v0.2.0 の完了条件とする

### NFR-011 自動監視とローカル通知の分離（MVP後）

- 自動監視のスケジューリング、OS 通知、タスクバー／Dock バッジを、それぞれ差し替え可能なサービス境界として設計する
- `Argus.Core` は Avalonia、Windows App SDK、AppKit、UserNotifications などの UI または OS 固有 API を参照しない
- 自動監視は既存の `CheckCoordinator` を利用し、手動チェックと結果判定、保存、エラー時のデータ保護を共通化する
- OS のログイン時起動、スケジュール実行、通知権限などの OS 固有制約を利用者へ明示する
- OS 通知へ比較対象の全文や秘密情報を含めない
- 自動監視と通知が失敗しても、最後に正常に保存された比較用データを破壊しない
- 自動監視、通知、バッジの主要な状態判定を OS に依存しない自動テストで検証できること

## 9. データ要件

### 9.1 監視対象

初期 MVP の監視対象は次の項目を保持します。

| 項目 | 用途 | 初期 MVP での確定状況 |
| --- | --- | --- |
| 名前 | 一覧上で監視対象を識別する | 必須 |
| URL | Web ページの取得とブラウザ起動に使用する | 必須。絶対HTTP/HTTPS URL |
| 監視モード | 比較方式を指定する | 必須。HTMLテキスト、HTML全体、CSSセレクタから選択 |
| CSS セレクタ | CSSセレクタ比較の抽出範囲を指定する | CSSセレクタ比較の場合のみ必須 |
| 有効 / 無効 | チェック対象に含めるかを指定する | 必須。新規追加時は有効 |
| メモ | ユーザー用の補足情報 | 任意 |
| 前回の比較用データ | 更新有無の判定と差分表示に使用する | ハッシュと直近の比較対象内容を正常チェック後に保持 |

サイト種別は保存項目に含めません。CSS セレクタは省略可能な項目として既存 JSON との後方互換性を維持します。差分表示用の比較対象内容も省略可能な項目とし、内容を持たない既存JSONを読み込めるようにします。保存するのは直近の正常チェック結果だけで、履歴は保持しません。

### 9.2 保存形式

- 保存形式は JSON とする
- 想定保存先は `%APPDATA%\Argus\targets.json` とする
- 初期 MVP では外部 DB を使用しない
- 運用中の `targets.json` は schema v1 とし、前回の比較用データを含む
- 設定移行用の JSON は運用中の `targets.json` と別のポータブル形式とし、監視対象の編集可能な設定だけを含む
- 設定移行用の JSON の具体的な構造とバージョン管理は `Design/design.md` で定義する

### 9.3 自動監視と通知の状態（MVP後）

- 自動監視の有効状態と実行間隔を保存できる
- アプリが起動していない時間帯にも監視する設定を保存できる
- 通知の有効状態を保存できる
- 未確認の更新あり状態は監視対象単位で保持し、アプリ再起動後もバッジ件数を復元できる
- 未確認件数はチェック履歴や通知履歴ではなく、現在確認されていない更新あり対象の集計値として扱う
- 監視対象を削除または設定変更した場合、不要になった未確認状態を残さない
- 自動監視と通知の設定は、既存の schema v1 JSON と後方互換性を保てる形式で保存する。具体的な保存先とバージョン管理は `Design/design.md` で定義する

## 10. 代表的な利用シナリオ

### UC-001 初回チェック

1. ユーザーが Argus を起動する
2. Argus が JSON から監視対象を読み込む
3. ユーザーがチェック操作を実行する
4. Argus が対象ページを取得して正規化する
5. 前回データが存在しないため「初回取得」と表示する
6. Argus が今回の正常なデータを保存する

### UC-002 更新なし

1. ユーザーがチェック操作を実行する
2. Argus が対象ページを取得して正規化する
3. Argus が前回データと比較する
4. 内容が同一であるため「更新なし」と表示する
5. Argus が正常な結果を保存する

### UC-003 更新あり

1. ユーザーがチェック操作を実行する
2. Argus が対象ページを取得して正規化する
3. Argus が前回データと比較する
4. 内容が異なるため「更新あり」と表示する
5. Argus が前回と今回の比較対象を差分表示用に保持する
6. ユーザーが差分表示操作を実行し、変更箇所を確認する
7. Argus が今回の正常なデータを保存する
8. ユーザーが対象ページを既定ブラウザで開く

### UC-004 チェックエラー

1. ユーザーがチェック操作を実行する
2. Web ページの取得または比較処理に失敗する
3. Argus が対象を「エラー」と表示する
4. Argus は対象の前回データを上書きしない
5. 他の監視対象のチェック結果は維持される

### UC-005 監視対象の管理

1. ユーザーが追加操作を実行する
2. Argus が監視対象の入力画面を表示する
3. ユーザーが名前、URLなどを入力して保存する
4. Argus が入力を検証し、JSONへ保存する
5. Argus が保存した監視対象を一覧へ反映する
6. ユーザーは一覧から対象を選び、編集または削除できる

### UC-006 更新内容の確認

1. ユーザーが更新ありの監視対象を一覧から選択する
2. ユーザーが差分表示操作を実行する
3. Argus が前回の比較対象と今回の比較対象を比較し、追加、削除、変更を表示する
4. ユーザーが差分を確認してダイアログを閉じる

### UC-007 設定の移行（MVP後）

1. ユーザーがメイン画面から設定のエクスポート操作を実行する
2. Argus が保存先を尋ね、監視対象の編集可能な設定だけをポータブル JSON として保存する
3. ユーザーが別の環境で設定のインポート操作を実行する
4. Argus が JSON の形式、バージョン、全監視対象の入力値を検証する
5. ユーザーが現在の設定を置き換えることを確認する
6. Argus が設定を反映し、インポートした対象を「初回取得」として一覧へ表示する
7. 検証、確認、保存のいずれかに失敗した場合は、現在の設定を維持する

### UC-008 自動監視による更新検出（MVP後）

1. ユーザーが自動監視を有効にし、実行間隔を設定する
2. Argus が設定した間隔で有効な監視対象をチェックする
3. Argus が更新あり、更新なし、初回取得、エラーのいずれかを判定する
4. Argus が正常な結果だけを保存し、エラー時は前回の正常な比較用データを維持する
5. ユーザーが自動監視を無効にすると、以後の自動チェックを停止する

### UC-009 更新通知の確認（MVP後）

1. 自動チェックで監視対象が更新ありと判定される
2. Argus が OS 標準のローカル通知を表示し、未確認件数バッジを更新する
3. ユーザーが通知を選択するか、Argus の一覧上で確認操作を実行する
4. Argus が該当する監視対象を表示し、対象を確認済みとして扱う
5. Argus が未確認件数を再計算し、0 件の場合はバッジを消去する

## 13. 機能の完了判定

機能実装は、少なくとも次の条件をすべて満たした場合に完了とします。

- Windows と macOS 上で Avalonia アプリを起動できる
- JSON から複数の監視対象を読み込める
- 読み込んだ監視対象を一覧表示できる
- 監視対象を画面から追加、編集、削除できる
- 追加、編集、削除した内容がJSONへ保存され、再起動後も反映される
- ユーザー操作によって更新チェックを実行できる
- 全件チェックと選択項目チェックを使い分けられる
- チェック実行中に新たなチェックを開始できる
- HTML テキストを正規化して前回データと比較できる
- 初回取得、更新なし、更新あり、エラーを正しく判定できる
- 判定結果を一覧へ表示できる
- 正常終了したチェック結果を JSON へ保存できる
- エラー時に前回の正常データが保持される
- アプリ再起動後も保存した前回データを利用できる
- 選択した監視対象を OS の既定ブラウザで開ける
- UI とチェックロジックが分離されている
- Fluent Themeとライト／ダーク表示がメイン画面と監視対象編集画面へ一貫して適用されている

- Core の主要な振る舞いに対応する自動テストが存在する
