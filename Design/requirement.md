- 文書名: Argus 要件定義書

本書は、`Design/project-overview.md` に記載された構想から、Argus の初期 MVP に必要な要件を抽出して整理したものです。

「今後の予定」として記載された内容は初期 MVP の必須要件に含めず、将来候補として分離します。プロジェクト構想だけでは判断できない事項は「要確認事項」として記載します。

---

## 2. 背景

ユーザーは、小説サイト、ブログ、お知らせページ、配布ページ、更新履歴ページなど、複数の Web ページをブラウザで個別に開き、更新の有無を確認しています。

この確認作業には手間がかかるため、登録済みの複数ページを一括で確認し、前回確認時からの更新有無を把握できるデスクトップアプリを提供します。

---

## 3. 目的

Argus の目的は、ユーザーが任意のタイミングで更新チェックを実行し、登録した Web ページが前回確認時から変化したかを一覧で確認できるようにすることです。

初期 MVP では、高度な自動監視ツールではなく、次の利用体験を実現することを目標とします。

1. ユーザーが PC 上で Argus を起動する
2. 登録済みの監視対象を一覧で確認する
3. ユーザーがチェック操作を実行する
4. 各ページの更新状態を一覧で確認する
5. 必要なページを既定のブラウザで開く

---

## 4. 用語

| 用語 | 定義 |
| --- | --- |
| 監視対象 | 更新確認の対象として Argus に登録された Web ページ |
| チェック | ユーザー操作により Web ページを取得し、前回データと比較する処理 |
| 前回データ | 直前に正常終了したチェックで保存された比較用データ |
| 初回取得 | 比較可能な前回データが存在せず、今回の取得内容を基準として保存した状態 |
| 更新なし | 今回取得した比較対象の内容が前回データと同一である状態 |
| 更新あり | 今回取得した比較対象の内容が前回データと異なる状態 |
| エラー | Web ページの取得またはチェック処理を正常に完了できなかった状態 |
| HTML テキスト比較 | HTML から比較に不要な要素を除去してテキスト化し、正規化した内容を比較する方式 |
| HTML 全体比較 | 取得した HTML 文字列全体を比較する方式 |
| CSS セレクタ比較 | CSS セレクタに一致する要素だけを抽出して比較する方式 |

---

## 5. 対象範囲

### 5.1 初期 MVP の対象

- Windows デスクトップアプリとして起動する
- JSON ファイルから監視対象と前回データを読み込む
- 登録済みの監視対象を一覧表示する
- 監視対象を画面から追加、編集、削除する
- ユーザー操作によって手動チェックを開始する
- HTML テキスト比較によって更新有無を判定する
- HTML 全体比較または CSS セレクタ比較を監視対象ごとに選択できる
- チェック結果を一覧へ反映する
- 正常終了したチェック結果を JSON ファイルへ保存する
- 選択した監視対象の URL を Windows の既定ブラウザで開く

### 5.2 初期 MVP の対象外

- 自動チェック
- 常駐監視
- スケジュール実行
- LINE 通知
- Slack 通知
- メール通知
- ログイン必須サイトの監視
- CAPTCHA が必要なサイトの監視
- JavaScript 実行後の SPA 解析
- Playwright などを利用したブラウザレンダリング
- 外部データベースとの連携
- 小説サイト向け最新エピソード比較
- 差分内容の表示
- チェック履歴の表示
- 最新話 URL を直接開く機能
- Wails、Tauri、Avalonia など、WinForms 以外の UI 技術への移行

## 6. 利用者

初期 MVP の利用者は、Windows 10 または Windows 11 を使用し、複数の公開 Web ページの更新有無を任意のタイミングで確認したい個人ユーザーとします。

初期 MVP では複数ユーザー、アカウント、権限管理を扱いません。

## 7. 機能要件

### FR-001 アプリケーションの起動

Argus は、Windows デスクトップアプリとして起動できなければなりません。

受け入れ条件:

- Windows 10 または Windows 11 上でアプリを起動できる
- 起動後に監視対象の一覧画面が表示される

### FR-002 監視対象データの読み込み

Argus は、起動時に所定の JSON ファイルから監視対象と前回チェック結果を読み込まなければなりません。

想定保存先:

```text
%APPDATA%\Argus\targets.json
```

監視対象が保持する項目:

- ID
- 名前
- URL
- 監視モード
- 有効 / 無効
- メモ
- 前回の比較用データ

受け入れ条件:

- 正常な JSON ファイルから監視対象を復元できる
- 復元した監視対象が一覧へ表示される
- JSONが空、不正、または未対応の形式の場合はエラーを表示する
- JSONを正常に読み込めない場合は、チェック、監視対象管理、ブラウザ起動などの主要操作を無効化する
- JSONを正常に読み込めない場合は、既存ファイルを上書きしない

具体的な必須項目、初期値、JSONスキーマ、ファイル状態ごとの動作は `Design/design.md` で定義します。

### FR-003 監視対象の一覧表示

Argus は、読み込んだ監視対象を一覧表示しなければなりません。

一覧では、少なくとも各監視対象を識別でき、チェック結果を確認できなければなりません。

受け入れ条件:

- 複数の監視対象を一覧表示できる
- 各監視対象の名前または URL を確認できる
- 各監視対象の現在のチェック状態を確認できる

一覧へ表示する列、並び順、無効な監視対象の表示方法は `Design/design.md` で定義します。初期 MVP では絞り込み機能を設けません。

### FR-004 手動チェックの開始

Argus は、ユーザーが画面上のチェック操作を行ったときに、登録済みの監視対象に対する更新チェックを開始しなければなりません。

チェック操作は、次の二つに分けます。

- 全件チェック: 有効な監視対象をすべてチェックする
- 選択項目チェック: 一覧で選択した有効な監視対象だけをチェックする

チェック処理の実行中も、ユーザーによる新たなチェック操作を許可します。同じ監視対象がチェック中の場合も、再度チェックを開始できるものとします。

受け入れ条件:

- ユーザー操作がない状態で自動的にチェックを開始しない
- 全件チェックによって、有効な監視対象を一度の操作ですべて確認できる
- 選択項目チェックによって、一覧で選択した有効な監視対象だけを確認できる
- チェック処理の実行中でも、全件チェックまたは選択項目チェックを新たに開始できる
- 同じ監視対象のチェック処理が実行中でも、その監視対象を再度チェックできる

備考:

- 同じ監視対象のチェックが重複した場合、画面には時系列で最後に完了したチェックの結果を表示します。
- 最後に完了したチェックが正常終了した場合は、その結果を前回データとして保存します。
- 最後に完了したチェックがエラーの場合は、画面にエラーを表示しますが、前回の正常なデータは上書きしません。

### FR-005 Web ページの取得

Argus は、チェック対象の URL から HTML を取得しなければなりません。

受け入れ条件:

- 公開されている HTTP または HTTPS の Web ページを取得できる
- HTTPヘッダー、BOM、HTML内の `meta charset` を用いて文字コードを判定できる
- 取得に失敗した場合は、その監視対象をエラーとして扱う
- 一つの監視対象でエラーが発生しても、他の監視対象の結果を失わない

備考:

- タイムアウト、リダイレクト、User-Agent、同時取得数は `Design/design.md` で定義します。
- 文字コード判定の優先順位は `Design/design.md` で定義します。

### FR-006 HTML テキストの正規化

Argus は、取得した HTML をテキスト比較に適した形式へ正規化しなければなりません。

初期 MVP の正規化では、少なくとも次を行います。

- `script` 要素の内容を比較対象から除外する
- `style` 要素の内容を比較対象から除外する
- HTML コメントを比較対象から除外する
- 空白と改行の差異を正規化する
- HTML をテキスト化する

受け入れ条件:

- `script`、`style`、HTML コメントだけの変化を更新として検知しない
- 正規化によって同一とみなせる空白または改行だけの変化を更新として検知しない
- ユーザーが閲覧する本文テキストが変化した場合は、比較結果へ反映される

備考:

- HTML の不正な構造、エンティティ、改行および連続空白の具体的な正規化規則は設計で定義します。

### FR-014 HTML 全体比較

Argus は、監視対象ごとに取得した HTML 文字列全体を比較対象として選択できなければなりません。

受け入れ条件:

- HTML 全体比較では、取得した HTML 文字列を加工せず比較用ハッシュへ変換する
- 要素、属性、コメント、空白のいずれかが変化した場合は比較結果へ反映される
- 従来の HTML テキスト比較を選択した対象の動作は変わらない

### FR-015 CSS セレクタ比較

Argus は、監視対象ごとに CSS セレクタを指定し、一致する要素だけを比較対象として選択できなければなりません。

受け入れ条件:

- CSS セレクタ比較を選択した場合は、CSS セレクタを必須とする
- 一致する全要素の外側 HTML を文書順に連結して比較する
- 一致要素内の要素、属性、テキストの変化が比較結果へ反映される
- 一致要素の外側だけの変化は比較結果へ反映されない
- CSS セレクタが不正、または一致する要素がない場合はエラーとして扱う
- CSS セレクタ比較のエラー時は前回の正常な比較用データを上書きしない

### FR-007 更新状態の判定

Argus は、今回取得して正規化した内容と前回データを比較し、監視対象ごとの状態を判定しなければなりません。

状態は次のいずれかとします。

| 状態 | 条件 |
| --- | --- |
| 未確認 | 現在の起動中にまだチェックしていない |
| 初回取得 | 前回データが存在せず、今回の取得に成功した |
| 更新なし | 今回の内容と前回データが同一だった |
| 更新あり | 今回の内容と前回データが異なった |
| エラー | 取得または比較処理に失敗した |

受け入れ条件:

- 前回データがない正常取得を「更新あり」ではなく「初回取得」と判定する
- 正規化後の内容が同一の場合は「更新なし」と判定する
- 正規化後の内容が異なる場合は「更新あり」と判定する
- 処理に失敗した場合は「エラー」と判定する

### FR-008 チェック結果の表示

Argus は、チェック結果を監視対象の一覧へ反映しなければなりません。

受け入れ条件:

- 監視対象ごとに「未確認」「初回取得」「更新なし」「更新あり」「エラー」のいずれかを確認できる
- 複数の監視対象について、それぞれの結果を区別できる

チェック日時とエラー概要の表示方法は `Design/design.md` で定義します。色やアイコンによる追加表現は初期 MVP の必須要件としません。

### FR-009 正常結果の保存

Argus は、正常にチェックできた監視対象について、次回比較に必要なデータを JSON ファイルへ保存しなければなりません。

受け入れ条件:

- 初回取得、更新なし、更新ありのチェック完了後に、次回比較に必要なデータを保存できる
- アプリを終了して再起動した後も、保存済みデータを前回データとして利用できる
- 保存先は `%APPDATA%\Argus\targets.json` を基本とする

### FR-010 エラー時の前回データ保護

Argus は、チェックに失敗した監視対象の前回データを上書きしてはなりません。

受け入れ条件:

- 通信エラーが発生しても、その監視対象の前回の正常な比較用データが保持される
- 比較処理でエラーが発生しても、その監視対象の前回の正常な比較用データが保持される
- 次回の正常なチェックで、保持された前回データと比較できる

### FR-011 既定ブラウザで開く

Argus は、ユーザーが選択した監視対象の URL を Windows の既定ブラウザで開けなければなりません。

受け入れ条件:

- 一覧から監視対象を選択して、その URL を開く操作を実行できる
- URL が Windows の既定ブラウザで開かれる
- URL を開けない場合にアプリが異常終了しない

### FR-012 監視対象の追加・編集・削除

Argus は、監視対象を画面から追加、編集、削除できなければなりません。

追加または編集できる項目は次のとおりです。

- 名前
- URL
- 監視モード
- 有効 / 無効
- メモ

選択できる監視モードは HTML テキスト比較、HTML 全体比較、CSS セレクタ比較とします。CSS セレクタ比較では CSS セレクタも入力します。

受け入れ条件:

- 新しい監視対象を追加し、一覧へ反映できる
- 既存の監視対象を選択し、その内容を編集できる
- 既存の監視対象を確認操作後に削除できる
- 名前が空または空白だけの場合は保存できない
- URLが絶対HTTP/HTTPS URLでない場合は保存できない
- 追加、編集、削除の結果がJSONへ保存される
- アプリを再起動しても追加または編集した内容が復元され、削除した対象が復元されない
- 保存に失敗した場合は、画面上および保存済みの変更前データを維持する
- URLを変更した場合は前回の比較データを破棄し、次回の正常チェックを「初回取得」として扱う
- 監視モードまたは CSS セレクタを変更した場合は前回の比較データを破棄し、次回の正常チェックを「初回取得」として扱う
- チェック実行中の監視対象は編集または削除できない

### FR-013 コピーライト、バージョン、ビルド種別の表示

Argus は、メイン画面にコピーライト表記とアプリケーションのバージョン番号を表示しなければなりません。

コピーライトは次の表記とします。

```text
Copyright © 2026 SIA-ACT
```

デバッグビルドでは、開発用ビルドであることをユーザーが識別できる表示を追加しなければなりません。Releaseビルドではデバッグ表示を行いません。

受け入れ条件:

- メイン画面上で `Copyright © 2026 SIA-ACT` を確認できる
- メイン画面上でバージョン番号を確認できる
- コピーライト表記はビルド時のアセンブリ情報から取得する
- 表示するバージョン番号はビルド時のアセンブリ情報から取得する
- コピーライトとバージョン番号を画面コードへ直接記述しない
- Debug構成でビルドしたアプリには `DEBUG` と表示される
- Release構成でビルドしたアプリには `DEBUG` が表示されない
- バージョン番号とデバッグ表示が、通常の操作やメッセージ表示を妨げない

## 8. 非機能要件

### NFR-001 対応環境

- Windows 10 および Windows 11 を対象とする
- UI には WinForms を使用する
- C# および .NET 8 以降を使用する

### NFR-002 配布

配布形式は、self-contained single-file executable を候補とします。

備考:

- 初期配布対象はWindows x64とします。
- ファイルサイズと更新方法は要確認とします。

### NFR-003 データ永続化

- 監視対象と前回チェック結果は JSON 形式でローカルへ保存する
- 初期 MVP では外部データベースを使用しない
- チェックエラーによって前回の正常データを失わない

### NFR-004 誤検知の抑制

- 初期 MVP の標準監視モードには HTML テキスト比較を使用する
- 比較前に `script`、`style`、HTML コメントを除外する
- 比較前に空白と改行を正規化する
- 誤検知を抑えるための追加方式は、初期 MVP の完了後に検討する

### NFR-005 保守性と移植性

- UI 処理と更新チェックロジックを分離する
- HTML 取得、正規化、比較、保存の責務を分離する
- 将来 WinForms 以外の UI へ再構築する場合に、チェックロジックを再利用できる構成とする

### NFR-006 操作方針

- 更新チェックはユーザーの明示的な操作によって開始する
- 初期 MVP ではバックグラウンドでの自動監視を行わない
- PC を起動し、Argus を開いてチェック操作を行うだけで更新有無を把握できることを目標とする
- アプリ終了時は実行中または待機中のチェックへ即時キャンセルを通知し、完了を待たずに終了する

### NFR-007 テスト可能性と品質保証

- UI と Core のロジックを分離し、Core の振る舞いを UI なしで自動テストできること
- HTML の正規化、比較、状態判定、データ保護の主要な振る舞いを自動テストで検証できること
- 初回取得、更新なし、更新あり、通信エラーを自動テストで検証すること
- エラー時に前回の正常データが保持されることを自動テストで検証すること
- 自動テストは実際の Web サイトの状態に依存せず、繰り返し同じ結果を得られること
- テスト可能な機能は、原則として失敗するテスト、最小限の実装、リファクタリングの順で開発すること

### NFR-008 UIテーマと視認性

- UI全体のテーマを「夏」とする
- 青空、海、水、白い雲、夏の日差しを想起させる、明るく爽やかな配色とする
- 背景、文字、ボタン、選択状態、無効状態、チェック結果の色を画面間で統一する
- 文字と背景のコントラストを確保し、長時間使用しても読みにくくならないこと
- 更新状態やエラー状態は色だけで表現せず、状態名の文字を必ず併記すること
- 操作可能、選択中、フォーカス中、無効の各状態を視覚的に区別できること

## 9. データ要件

### 9.1 監視対象

初期 MVP の監視対象は次の項目を保持します。

| 項目 | 用途 | 初期 MVP での確定状況 |
| --- | --- | --- |
| 名前 | 一覧上で監視対象を識別する | 必須 |
| URL | Web ページの取得とブラウザ起動に使用する | 必須。絶対HTTP/HTTPS URL |
| 監視モード | 比較方式を指定する | 必須。HTMLテキスト、HTML全体、CSSセレクタから選択 |
| CSS セレクタ | CSSセレクタ比較の抽出範囲を指定する | CSSセレクタ比較の場合のみ必須 |
| 有効 / 無効 | チェック対象に含めるかを指定する | 必須。新規追加時は有効 |
| メモ | ユーザー用の補足情報 | 任意 |
| 前回の比較用データ | 更新有無の比較に使用する | 正常チェック後に保持 |

サイト種別は保存項目に含めません。CSS セレクタは省略可能な項目として既存 JSON との後方互換性を維持します。

### 9.2 保存形式

- 保存形式は JSON とする
- 想定保存先は `%APPDATA%\Argus\targets.json` とする
- 初期 MVP では外部 DB を使用しない
- JSON の具体的な構造、バージョン管理、バックアップ方法は設計で定義する

## 10. 代表的な利用シナリオ

### UC-001 初回チェック

1. ユーザーが Argus を起動する
2. Argus が JSON から監視対象を読み込む
3. ユーザーがチェック操作を実行する
4. Argus が対象ページを取得して正規化する
5. 前回データが存在しないため「初回取得」と表示する
6. Argus が今回の正常なデータを保存する

### UC-002 更新なし

1. ユーザーがチェック操作を実行する
2. Argus が対象ページを取得して正規化する
3. Argus が前回データと比較する
4. 内容が同一であるため「更新なし」と表示する
5. Argus が正常な結果を保存する

### UC-003 更新あり

1. ユーザーがチェック操作を実行する
2. Argus が対象ページを取得して正規化する
3. Argus が前回データと比較する
4. 内容が異なるため「更新あり」と表示する
5. Argus が今回の正常なデータを保存する
6. ユーザーが対象ページを既定ブラウザで開く

### UC-004 チェックエラー

1. ユーザーがチェック操作を実行する
2. Web ページの取得または比較処理に失敗する
3. Argus が対象を「エラー」と表示する
4. Argus は対象の前回データを上書きしない
5. 他の監視対象のチェック結果は維持される

### UC-005 監視対象の管理

1. ユーザーが追加操作を実行する
2. Argus が監視対象の入力画面を表示する
3. ユーザーが名前、URLなどを入力して保存する
4. Argus が入力を検証し、JSONへ保存する
5. Argus が保存した監視対象を一覧へ反映する
6. ユーザーは一覧から対象を選び、編集または削除できる

## 12. 要確認事項

プロジェクト構想だけでは確定できないため、設計へ進む前に次の事項を確認する必要があります。

### 優先度: 高

- 現時点で高優先度の要確認事項はありません。

### 優先度: 中

- エラー内容をどの程度ユーザーへ表示するか

### 優先度: 低

- アプリのログを保存するか
- 設定や保存データのバックアップを作成するか
- JSON スキーマの将来バージョン管理方法

## 13. 初期 MVP の完了判定

初期 MVP は、少なくとも次の条件をすべて満たした場合に完了とします。

- Windows 上で WinForms アプリを起動できる
- JSON から複数の監視対象を読み込める
- 読み込んだ監視対象を一覧表示できる
- 監視対象を画面から追加、編集、削除できる
- 追加、編集、削除した内容がJSONへ保存され、再起動後も反映される
- ユーザー操作によって更新チェックを実行できる
- 全件チェックと選択項目チェックを使い分けられる
- チェック実行中に新たなチェックを開始できる
- HTML テキストを正規化して前回データと比較できる
- 初回取得、更新なし、更新あり、エラーを正しく判定できる
- 判定結果を一覧へ表示できる
- 正常終了したチェック結果を JSON へ保存できる
- エラー時に前回の正常データが保持される
- アプリ再起動後も保存した前回データを利用できる
- 選択した監視対象を Windows の既定ブラウザで開ける
- UI とチェックロジックが分離されている
- 「夏」をテーマにした配色がメイン画面と監視対象編集画面へ一貫して適用されている
- 状態や操作可否を色だけに依存せず識別できる
- メイン画面で `Copyright © 2026 SIA-ACT` を確認できる
- メイン画面でバージョン番号を確認できる
- Debugビルドではデバッグ表示があり、Releaseビルドでは表示されない
- Core の主要な振る舞いに対応する自動テストが存在する
- 自動テストが実際の Web サイトへ依存せず、すべて成功する
