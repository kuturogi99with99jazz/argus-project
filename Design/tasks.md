## 2. ステータス管理

各タスクの `ステータス` は次のいずれかで管理します。

| ステータス | 意味 |
| --- | --- |
| 未着手 | 作業を開始していない |
| Red | 期待する振る舞いのテストを作成し、意図した理由で失敗することを確認中 |
| Green | テストを通す最小実装を作成中 |
| Refactor | 全テスト成功を維持しながら設計を改善中 |
| 検証中 | 自動テスト、手動確認、文書整合を確認中 |
| 完了 | 完了条件をすべて満たした |
| 保留 | 外部要因またはユーザー判断を待っている |

一度に複数の実装タスクを進行中にせず、依存関係を満たした最小のタスクを一つずつ進めます。

---

## 3. 共通実施ルール

各タスクでは次の順序を守ります。

1. 対応要件と設計箇所を読み直す
2. タスクのステータスを `Red` にする
3. 外部から観測できる振る舞いを表すテストを一つ追加する
4. テストが意図した理由で失敗することを確認する
5. ステータスを `Green` にし、テストを通す最小実装を行う
6. ステータスを `Refactor` にし、責務、命名、重複を改善する
7. 関連テストと影響範囲のテストを実行する
8. 必要な手動確認を行う
9. 要件、設計、タスク、実装、テストの整合を確認する
10. 完了条件を満たした場合だけステータスを `完了` にする

ドキュメント、プロジェクト構成、WinFormsデザイナーなど、テスト先行が適さない作業では、タスク内の「TDD例外」に理由と代替検証を記載します。

共通検証コマンド:

```powershell
dotnet restore
dotnet build Argus.sln
dotnet test Argus.sln
```

現在の単一WinFormsプロジェクトを `Argus.WinForms`、`Argus.Core`、`Argus.Core.Tests` に分割し、以降のTDDを開始できる状態にします。

- `Argus.Core.Tests` から `Argus.Core` を参照する

- テンプレート由来の無意味なテストを残さない

プロジェクト構成変更そのものには振る舞いテストを先行させません。代替として、参照方向、ビルド、テスト検出を検証します。

- `dotnet restore` が成功する
- `dotnet build Argus.sln` が警告・エラーなしで成功する
- `dotnet test Argus.sln` がテストプロジェクトを検出して成功する
- `Argus.Core` が `Argus.WinForms` を参照していない

- Debugビルド: 成功、警告0、エラー0
- Releaseビルド: 成功、警告0、エラー0
- Debugテスト実行: xUnitテストアセンブリを検出し、終了コード0
- Releaseテスト実行: xUnitテストアセンブリを検出し、終了コード0

- 参照方向: WinFormsとTestsからCoreへの一方向参照を確認

#### 完了条件

- 設計3.1の構成になっている
- 既存の空フォームを起動できる
